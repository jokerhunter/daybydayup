# 2022：换一个赛道，去和新能源设备打交道

## 这一年发生了什么

2022 年 5 月，我换了一家公司，投身一个**能源物联网平台**——支撑 50+ 新能源站点、设备数据实时采集与可视化。从「人与内容」的社区，切换到「机器与数据」的物联网，业务形态完全变了：

- 设备数据是**高频、持续、只追加**的，和社区帖子的读写模式截然不同；
- 指标计算是**有依赖关系的 DAG**，电费 = 电价 × 电量，而电量又依赖多个分表聚合……

## 技术上的变化

### 1. Spring Cloud Alibaba 全家桶

Nacos（注册发现 + 动态配置）、Sentinel（限流降级）、Gateway（路由）。从社区版的 Spring Cloud 到 Alibaba 系，体会最深的是**动态配置**的价值：限流阈值、开关灰度，改配置即生效，不用重新发版。

### 2. DAG 指标编排引擎（初版）

这是我这一年最投入的模块：指标之间有依赖关系，先算哪个、哪些能并行？第一版用同步遍历，复杂指标算完要 **3 分钟**——大屏盯着一个转圈的三分钟。这个数字埋下了第二年大优化的种子。

### 3. 前端进入 Vue3 + TypeScript 时代

设备监控大屏与**交互式拓扑图**（ECharts + 关系图），实时数据动态刷新。TypeScript 的类型系统让前后端接口契约第一次「编译期可验证」。同时用邻接表 + MySQL 递归 CTE + Redis 缓存解决**万级设备节点的层级查询**。

## 个人感悟

> 换行业的成本不是学新业务，而是**换一套心智模型**：社区想的是「人为什么会点赞」，物联网想的是「数据为什么迟到」。

这一年开始有意识地「深耕」而不是「追新」：把 JUC 的线程池、CAS、AQS 源码读了一遍。因为我发现，并发编程的所有坑，DAG 引擎里都会踩到。

**给技术人的一句话：框架会过时，但每一层 abstraction 背后的问题域是稳定的。**
