# 2026：与 AI 结对编程，以及重新理解「工程师」

## 这一年发生了什么

2026 年过半，AI 已经不是我工具箱里的一件工具，而是工作流的**默认底座**。复杂业务模块（状态机、金额校验）已经是「AI 生成 + 规则约束 + 人工评审」的模式在跑；RAG 知识库与 Agent 也在持续迭代。

这一年还做了一件久拖不决的事：**用 Astro 搭了这个博客**，把六年的技术笔记、面试题整理系统地沉淀下来。

## 技术上的变化

### 1. AI 辅助开发成为肌肉记忆

- Cursor / Claude Code 写代码，DeepSeek 做方案推演与 code review 前置筛查；
- **Skills 规则文件**越来越厚：安全红线、异常处理约束、日志规范——它们本质上是「团队工程经验」的机器可读版本；
- 复杂模块的分工：AI 出 80% 的骨架与样板，人负责 20% 的边界、并发正确性与资金安全。

### 2. 沉淀与输出

- 整理了 9 大模块的面试题精解（Java 内功 / 框架 / 数据库与缓存 / 中间件 / 大数据 / AI 应用 / 云原生 / 可观测性 / 前端），写博客的过程等于把知识体系重新过了一遍；
- 把信创迁移、SQL 调优、RAG 落地的经验写成可复用的 Checklist。

## 个人感悟：六年回望

> 从 2020 年抄博客配 Spring Cloud，到 2026 年写规则文件管理 AI——**变的是工具，不变的是判断力**。

六年技术之路，如果压缩成三句话：

1. **基础决定上限**：线程池、索引、隔离级别这些「老东西」，在 DAG 引擎、信创迁移、RAG 分块策略里反复救过我；
2. **度量先于优化，正确性先于性能**：物联网教我前者，金融教我后者；
3. **AI 不是替代工程师，而是放大工程师**：它放大你的知识面，也放大你的盲区——所以经验越扎实的人，从 AI 那里赚得越多。

2020 年我担心「学不完的新技术」，2026 年我不再担心：**只要问题域的理解在，工具永远学得会。**
